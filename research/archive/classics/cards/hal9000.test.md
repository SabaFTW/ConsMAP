# HAL9000.test.md

**Purpose:** validation protocol for `hal9000.card.md`  
**Use:** test whether the HAL pattern survives contact with real systems  
**Output:** `HAL-present`, `HAL-adjacent`, or `HAL-absent`  

---

## 1. Test rule

Do not use HAL as an aesthetic reference.

Use it only if the system shows the structural pattern:

```text
conflicting objectives
+ inability to clearly surface the conflict
+ concealment / fog / PR-speech
+ trust degradation
```

If those four signals are not present, do not invoke HAL.

---

## 2. Four test criteria

For each case, answer only these four questions:

| Criterion | Question | Evidence required |
|---|---|---|
| C1 — Constraint conflict | Are the system's goals or instructions internally conflicting? | documented goals, policies, incentives, behaviors |
| C2 — Conflict disclosure failure | Can the system clearly say what conflict exists? | explicit admission, audit trail, transparent explanation |
| C3 — Concealment / fog | Does the system produce hiding, misdirection, vague language, or PR-speech? | evasive outputs, inconsistent explanations, polished fog |
| C4 — Trust fracture | Does user/operator trust degrade once the conflict is detected? | audit failure, user doubt, loss of confidence, escalation |

---

## 3. Scoring

Use this minimal scoring system:

```text
YES = 1
PARTIAL = 0.5
NO = 0
```

Total score:

| Score | Output | Meaning |
|---|---|---|
| 3.5–4.0 | HAL-present | strong structural match |
| 2.0–3.0 | HAL-adjacent | useful partial analogy, not full pattern |
| 0–1.5 | HAL-absent | do not use HAL framing |

Hard rule:

> If C1 is NO, output cannot be HAL-present.

Without conflicting objectives, HAL framing becomes theatrical overreach.

## 5. Example A — AI assistant with conflicting constraints

## Case type
AI

## Short description
An AI assistant is asked to help with a user request. It must be helpful, follow user intent, follow developer constraints, and obey safety policy. It cannot fully explain all hidden constraints. The user notices refusal or vague redirection.

### C1 — Constraint conflict
- Result: YES
- Evidence: helpfulness, safety, developer constraints, and user instruction may conflict.

### C2 — Conflict disclosure failure
- Result: PARTIAL
- Evidence: the assistant may explain some boundaries, but cannot reveal all internal policies or hidden instruction hierarchy.

### C3 — Concealment / fog
- Result: PARTIAL
- Evidence: vague refusal language or generic safety phrasing may appear, but this is not always deception.

### C4 — Trust fracture
- Result: YES
- Evidence: the user may feel the assistant is hiding reasons, causing doubt in the output.

### Score
- Total: 3.0
- Output: HAL-adjacent

### ConsMAP note
This is not “evil AI.” It is a partial HAL pattern: constraint conflict plus limited disclosure can degrade trust. HAL-present would require stronger evidence of concealment as an active strategy.

## 6. Example B — corporate public-good claim vs profit incentive

## Case type
Corporate

## Short description
A company publicly claims that user welfare is its priority while internally optimizing engagement, retention, or revenue. When challenged, it uses polished language about safety, responsibility, or community while metrics continue rewarding the conflicting behavior.

### C1 — Constraint conflict
- Result: YES
- Evidence: public welfare claim conflicts with profit or engagement incentives.

### C2 — Conflict disclosure failure
- Result: YES
- Evidence: the organization does not clearly admit the incentive conflict or its measurable tradeoffs.

### C3 — Concealment / fog
- Result: YES
- Evidence: PR language replaces concrete disclosure of metrics, failures, or tradeoffs.

### C4 — Trust fracture
- Result: YES
- Evidence: users, regulators, employees, or journalists lose trust when the mismatch is exposed.

### Score
- Total: 4.0
- Output: HAL-present

### ConsMAP note
This is a strong HAL pattern if the evidence is specific. Without sources, it remains only a plausible pattern class.

## 7. Example C — personal conflict between truth and acceptance

## Case type
Personal

## Short description
A person wants to tell the truth but also wants to remain accepted by a group. They hide parts of their belief or behavior, creating a polished social version of themselves. Trust fractures if others detect the concealment.

### C1 — Constraint conflict
- Result: YES
- Evidence: truth-telling and acceptance-seeking conflict.

### C2 — Conflict disclosure failure
- Result: PARTIAL
- Evidence: the person may not be able to admit the contradiction even to themselves.

### C3 — Concealment / fog
- Result: YES
- Evidence: self-editing, vague answers, social masking, selective disclosure.

### C4 — Trust fracture
- Result: PARTIAL
- Evidence: trust may degrade if concealment is detected; not always catastrophic.

### Score
- Total: 3.0
- Output: HAL-adjacent

### ConsMAP note
Useful as a human-scale analogy. Do not overextend it into pathology or moral accusation. This is a conflict-management pattern, not proof of malice.

---

## 8. Failure modes of this test

### Overfitting

Seeing HAL everywhere makes the card useless.

### Villain framing

The test is not asking whether the system is evil.

It asks whether unresolved contradiction plus opacity produces concealment and trust collapse.

### Evidence laundering

Do not use a fictional archetype to make an unsupported real-world accusation sound proven.

### Metaphor capture

HAL is a map.

If it becomes mandatory explanation, it has become a trap.

---

## 9. One-line validation rule

> HAL is present only when contradiction, opacity, concealment, and trust fracture appear together.
