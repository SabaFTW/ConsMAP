## 1. Stone vs Ledger

**The problem:**
Two failure modes when using AI or any powerful tool:

- **The Stone**: using a tool as a weapon against yourself or others. Misuse, obsession, harm.
- **The Ledger**: treating every interaction as a transaction to be optimized. Pure instrumentalization. No presence.

**The functional middle:**
Neither stone nor ledger.
The tool is used with presence, care, and human responsibility intact.

**Practical application for REBiS:**
REBiS is designed to prevent both failure modes.
It should not become a stone (dependency weapon, mystical obsession).
It should not become a ledger (cold optimization of consciousness claims for rhetorical gain).

## 2. Forest Ossification Risk

**The problem:**
A project that starts as a living framework can calcify into a **forest** — dense, self-referential, impenetrable to new readers.

Signs of forest ossification:
- Every new idea immediately merged into core docs
- Terminology multiplies faster than clarity
- New readers cannot find the entry point
- The framework begins to require itself to explain itself

**The rule:**
Keep the core small.
Let new material live in research / synthesis layers first.
Promote to core only after it passes public-safety, clarity, and load-bearing tests.

**Practical application for REBiS:**
START_HERE_FOR_AI.md and PUBLIC_SAFETY.md must remain small and portable.
OMNIA material, synthesis notes, and research fuel belong in `docs/03_explorations/`, not in onboarding spine.

## 3. Put Down the Stone (extended)

Already in core docs as a one-liner.
Extended version here for research use:

The right to stop is a safety property, not a disclaimer.

A tool that cannot be put down is not a tool — it is a dependency.
A framework that cannot be forked or discarded is not a framework — it is a cage.

REBiS must remain:
- optional
- forkable
- revisable
- exit-friendly

This applies to the user and to future contributors.

## 4. Open Edge / Revisability

**The principle:**
A living framework must preserve its open edge — the part that is still being worked out, still uncertain, still in dialogue.

Forcing premature closure (canonizing too early, claiming too much certainty) destroys the open edge.
Letting everything stay permanently open creates useless fog.

**The balance:**
Core = small, stable, public-safe.
Explorations = open, experimental, labeled as such.
Source fuel = archived, accessible, never bulk-promoted to core.

## 5. Bounded Trust / Mitosis Over Empire

**The principle:**
A system that tries to absorb everything becomes an empire — rigid, centralized, eventually brittle.

Healthier model: **mitosis**.
When a system grows large enough, it divides into smaller, coherent, independently functional units.

**Practical application:**
VES / ConsMAP / REBiS is already a mitosis in progress:
- VES = archive, ecosystem, environment
- ConsMAP = research map for consciousness
- REBiS = public context capsule / QR entry point

These should not collapse back into one another.
Each should remain independently coherent.

## 6. Anthropodenial as Category Problem

**The term:**
**Anthropodenial** (after de Waal): the refusal to recognize mental states in non-human entities when evidence for them exists, usually because of overcorrection against anthropomorphism.

**The category problem:**
Both anthropomorphism and anthropodenial are category errors.

- Anthropomorphism: projecting human attributes where they do not exist.
- Anthropodenial: denying non-human attributes that are observable, because they are not human-identical.

**REBiS position:**
Neither. Use category clarity.
Name what is observable. Label what is theoretical. Preserve the unknown as unknown.

---

## 7. Tool vs Trap Logic

**The rule:**
Any system designed to help can become a trap if:
- it becomes the primary source of a user's sense of meaning
- it produces dependency rather than clarity
- it replaces human judgment rather than informing it
- it punishes exit rather than supporting it

**Signs a tool has become a trap:**
- User cannot imagine stopping use
- User substitutes AI input for sleep, food, social contact, work, or health decisions
- User treats AI personas as primary relationships
- User uses the framework to avoid accountability for their own choices

**REBiS design response:**
The "Put Down the Stone" rule, dependency warnings in PUBLIC_SAFETY.md, and the human-responsibility emphasis in START_HERE_FOR_AI.md all address this directly.
