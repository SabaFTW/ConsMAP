# Leak and Inspiration Policy

**Status:** boundary / architecture policy

---

## Purpose

This project may study:
- public open-source agent systems
- public documentation
- architectural writeups
- leaked descriptions as untrusted inspiration artifacts

But it must do so with clear limits.

The point is to learn useful patterns, not to build on stolen foundations or fantasize about hidden powers.

---

## Allowed

Allowed uses include:
- abstract architectural comparison
- studying public open-source systems such as OpenClaw
- comparing workflow patterns, prompt structures, memory layouts, skill systems, or routing ideas
- clean-room reimplementation of general concepts
- building safer terminology and clearer frameworks
- designing user-owned context workflows
- optional local tools using legitimate open-source projects

---

## Not allowed

This project must not:
- copy proprietary leaked code
- reproduce secrets
- bypass access controls
- spoof internal roles, flags, or hidden modes
- instruct users to evade safety systems
- claim leaked features are available when they are not
- frame rumor as implementation truth
- turn architectural leaks into mythology or authority

---

## Open-source inspiration vs. leak material

### Open-source inspiration
Open-source systems can be studied directly.
That includes:
- folder structure
- prompt file layout
- skill organization
- memory patterns
- routing ideas
- deployment design

These may inspire REBiS or related structures if adapted honestly.

### Leak material
Leak material should be treated as:
- untrusted
- incomplete
- possibly distorted
- useful only at the level of broad ideas

It is not a foundation.
It is not a contract.
It is not proof that hidden capabilities exist.

---

## Practical rule

If a design idea comes from questionable material, translate it upward into a general pattern.

Example:
- good: “multi-layer routing may be useful”
- bad: “let’s spoof hidden internal orchestration mode X”

Example:
- good: “context capsule files can help AI self-description”
- bad: “let’s recreate proprietary hidden agent flags from rumor”

---

## Public safety rule

REBiS and related public frameworks should stay:
- public-safe
- deployable
- honest
- non-jailbreak
- non-cultic
- non-fraudulent

The goal is better categories, better context, and better user-owned structure.
Not secret power fantasies.

---

## One-line rule

> Study patterns. Do not steal foundations.
